Case Study

Personal APP Demo – Airbnb-style Listings & Booking App

Role: Full-Stack / Frontend Engineer  ·  Type: Personal project inspired by Airbnb's core flows

Overview

ABNB is a full-stack web application inspired by Airbnb. It allows users to browse listings, view listing details, manage their own properties, and create bookings. I built this project to practice end-to-end product thinking: from UI layout and interactions to API design, data modeling, and authentication.

The focus of this case study is on how I designed the user experience for browsing, booking, and managing stays, and how I implemented those flows with React on the frontend and a RESTful backend.

Tech Stack

React Redux React Router JavaScript (ES6+) HTML5 CSS3 Flask (Python) SQLAlchemy PostgreSQL REST API

Goals

  • Recreate core Airbnb flows: browse listings, view details, manage stays, and create bookings.
  • Design a clean, card-based UI that is easy to scan and works well on desktop and tablet.
  • Practice building a full CRUD REST API with auth and relational data (users, listings, bookings, images).
  • Get comfortable with Redux state management and React Router for multi-page navigation.

UI/UX Design Process

1. Mapping the main user journeys

I started by defining the key flows:

  • Browse all listings from the homepage.
  • Filter and click into an individual listing.
  • Review photos, description, price, and existing reviews on the details page.
  • Choose dates and create a booking (authenticated users only).
  • As a host, create, edit, or delete listings you own, and see associated bookings.

From these journeys, I sketched low-fidelity wireframes: a tiled listing grid, a detail page with a main hero image and key info on the right, and a simple dashboard view for hosts.

2. Listing grid & card design

The homepage uses a responsive grid of listing cards. Each card highlights:

  • Cover photo
  • Location and title
  • Price per night
  • Average rating (if available)

I experimented with different card layouts and hover states to make it clear that each card is clickable, while keeping the design visually simple. This mirrors how real users quickly scan multiple options before deciding where to click.

3. Listing detail page

The detail page is designed around a clear information hierarchy: gallery, high-level summary, and details.

  • Hero image and secondary photo grid
  • Title, location, host info
  • Price, fees, and booking call-to-action
  • Description and amenity list
  • Reviews section (where implemented)

I used a sticky booking panel on larger screens so that users can always see the date picker and price while scrolling through content.

4. Auth & host flows

For hosts, I added a simple management view:

  • Create new listing with title, description, price, and images.
  • Edit existing listings.
  • Delete listings you no longer want to show.

This helped me think through validation, error states, and permissions (only owners can modify their listings).

Engineering Details

  • Implemented a RESTful backend using Flask and SQLAlchemy, modeling users, listings, bookings, and images with relational tables.
  • Built authentication (sign up, log in, protected routes) so users can create bookings and manage their own content.
  • Used React + Redux for global state: current user, listings data, booking information, and UI loading/error states.
  • Used React Router to implement nested routes for listing details and user dashboards.
  • Added form validation on both frontend and backend to prevent invalid bookings (for example, overlapping dates or missing required fields).

Challenges & Learnings

One of the main challenges was keeping the data model and UI in sync: when a user edits or deletes a listing, the changes need to appear immediately across different views (home page, detail page, host dashboard). Redux helped centralize this logic and made the UI more predictable.

The project was also a good exercise in designing clear, opinionated flows without copying Airbnb pixel by pixel. I focused on understanding why certain UX patterns work (like sticky booking panels and clean card layouts) and then re-implementing them in my own way.
