Case Study

Snorkel AI – Multi-Stage Labeling & Dataset Dashboard

Role: Frontend / UI Engineer  ·  Product: Enterprise AI labeling & monitoring platform

Overview

Snorkel AI provides an enterprise platform for creating, managing, and monitoring labeled datasets used to train ML models. I worked on the web application used by internal teams and external customers to label data, review quality, and monitor progress across multiple projects.

This case study focuses on the multi-stage labeling and dataset dashboard experience: how we designed the workflows, translated them into React components, and iterated based on feedback from ML and data teams.

Tech Stack

React TypeScript Redux Toolkit GraphQL Node.js PostgreSQL Jest Cypress Storybook (internal)

My Responsibilities

  • Worked with product, ML engineers, and designers to define user journeys for annotators, reviewers, and project owners.
  • Designed and implemented React/TypeScript components for labeling queues, review workflows, and project dashboards.
  • Integrated GraphQL APIs and managed client-side state with Redux Toolkit to keep complex UI flows predictable.
  • Wrote unit and integration tests (Jest, React Testing Library, Cypress) and participated in code reviews.

Design Process

1. Understanding the users & workflows

We first mapped out the different roles in the system: annotators who label data, reviewers who check quality, and project owners who monitor progress. Through discussions and feedback sessions, we identified pain-points in the existing tools:

  • Too many separate screens to complete one labeling task.
  • Hard to see which items were blocked, in review, or ready to ship.
  • Little visibility into label quality and disagreement across annotators.

2. Flow diagrams & wireframes

I worked with the designer to turn these findings into flow diagrams for the end-to-end task:

  • Pick up a task from the queue.
  • Label and submit, or flag for review.
  • Perform a second-pass review.
  • Surface status and quality in the project dashboard.

We started with low-fidelity wireframes showing a unified “task view” and a simplified project dashboard with clear status segments (Todo / In progress / In review / Done).

3. Iterating on the UI

After the first implementation, internal users tested the new flows in real projects. Their feedback led to several improvements:

  • Added keyboard shortcuts and focused navigation to speed up labeling.
  • Introduced clearer empty states and inline explanations for complex actions (for example, what happens when you “reject” a label).
  • Adjusted the dashboard layout so that key metrics (items labeled, disagreement rate, review backlog) appear above the fold.

Engineering Details

  • Built reusable React components for task headers, progress indicators, and action toolbars so different labeling UIs could share common patterns.
  • Used Redux Toolkit slices to manage queue state, filters, and optimistic updates when annotators completed tasks.
  • Connected to GraphQL APIs for project statistics, using normalized caching to keep the dashboard fast and responsive even with large datasets.
  • Wrote tests around critical flows such as “pick task → label → submit” and permission checks for different roles.

Impact & Learnings

The new experience reduced context-switching for annotators, made project status easier to understand for stakeholders, and gave the ML team clearer signals about label quality and backlog. For me, this project reinforced how important it is to:

  • Design around real workflows, not just individual screens.
  • Keep the React component structure aligned with the mental model of the users.
  • Use small, focused usability sessions to quickly validate UI changes with internal teams.
